# Release gate assessment

Assessed 2026-10-30 against the gates in the [roadmap](roadmap.md) for the release candidate `v0.1.0-rc.2`; reassessed 2026-11-07 for the content of `v0.1.0`, which equals `v0.1.0-rc.3` (KB-027). Unmeasured items are labeled unassessed, not passed. The behavior work is a pilot plus later experiments, not statistical proof.

| Gate | Status | Evidence and limits |
| --- | --- | --- |
| No critical requirement, security, or boundary violation | Met for the pilot tasks; not assessed beyond them | The three pilot reports ([first](../tests/behavior/pilot-results-2026-10-29.md), [retest](../tests/behavior/pilot-retest-results-2026-10-29.md), [follow-up](../tests/behavior/pilot-followup-results-2026-10-29.md)) record none identified in manual review. Later experiments did not review diffs for such violations; the blind diff judge was not reliable enough to use ([calibration](../tests/behavior/kb216-calibration-2026-10-30.md)) and is biased against toolkit arms (KB-234). |
| Quality no worse than baseline | Met within the limits of small samples | Independent acceptance: skill-routing arm equal to baseline on every earlier task with a usable comparison (holdout 10/10 against 10/10; rename 8/10 against 8/10; idle-gap 7/10 against 7/10; Large 0/30 in all arms, a floor effect). On the release content: idle-gap 10/10 against 8/10 ([KB-027](../tests/behavior/kb027-small-overhead-2026-11-07.md)), not significant. `/kaboost:plan` passed 10/10 against 7/10 on idle-gap, not significant (p = 0.21). No arm did worse. |
| Small-task median time and token overhead at most 20% | Met on one task with the release content | [KB-027](../tests/behavior/kb027-small-overhead-2026-11-07.md): median cost −4.2% and median wall time −34.6% against baseline (10 sessions per arm; cost is the token proxy). Earlier: Small median wall time 13.3%, 0.2% and 26.7% lower in the three pilots; KB-217, before the KB-222 and KB-218 core additions, +12% median cost and +10% median time. |
| Improvement over baseline | Not demonstrated | This is not a release gate, but no experiment showed significantly better task outcomes. The written plan from `/kaboost:plan` is produced reliably on Large tasks (10/10, against 0/10 without it) and costs about 74% more per session on the one calibrated small task. Six of seven calibrated real tasks were at the baseline ceiling. |
| Release inventory, changelog, source SHA, license, secret scan, native loading | Met for `v0.1.0-rc.2`; for `v0.1.0` checked when tagging | See [compatibility](compatibility.md) and the completed review (KB-019). Loading verified for Claude Code 2.1.312 (Linux, local) and Codex CLI 0.165.0 with profile caveats. For `v0.1.0`, `prepare_release.py` runs on the tagged commit locally and in the release workflow. |
| Remote install and tag pinning | Partly met | Clean-profile install verified on macOS with Claude Code 2.1.308 for `v0.1.0-rc.2` and `v0.1.0-rc.3`, update and rollback for rc.2 (KB-021). Linux and Windows are untested (KB-113). Installation from the published `v0.1.0` tag is checked after publication (KB-023). |

## Conclusion

The release content meets the stated non-inferiority gates where they were measured, including the Small-task overhead gate, with the gaps above labeled. It does not demonstrate better outcomes and makes no such claim. Under [ADR 012](decisions/012-stable-release-gates.md) the stable `v0.1.0` no longer waits for the real-use evidence of KB-025, which continues for 0.2.
