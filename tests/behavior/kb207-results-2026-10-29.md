# KB-207 routing and readiness trial — 2026-10-29

Eighteen isolated Claude Code 2.1.312 sessions used `claude-sonnet-5-5`,
medium effort, the [original frozen prompts and source commit](pilot-plan.md),
and the expanded permissions used in the [follow-up](pilot-followup-plan.md).
Three baseline/toolkit pairs per scenario alternated arm order. The toolkit
snapshot was `bd080a4187b1580ee470d090ef3d8ed7d25012f4`: core rules were
imported in the toolkit arm and its generated plugin was passed via
`--plugin-dir`. Baseline retained the trial project's original instructions.
The authenticated profile was reused, so account-level isolation is not claimed.
The Large prompt explicitly requests the pre-edit readiness items; this is not
an independent test of whether the agent classifies an unspecified task as
Large. The updated external evaluator checks the previously missed unknown
argument behavior, without adding it to the prompt.

The [per-arm record](kb207-results-2026-10-29.csv) contains observed usage,
timings, independent check exit codes, denials, discovery, and integrity checks.
Raw event streams, diffs, and trial checkouts are in
`/tmp/kaboost-kb207-20261029` and are not durable. Reported total model cost
was USD 1.3582; no human intervened during a session. All sessions reported the
specified model, returned exit 0, and retained the source HEAD and harness
files; skill discovery matched the expected arm. Exit 0 is not task acceptance.

| Scenario | Independent acceptance, baseline / toolkit | Observed routing and readiness |
| --- | --- | --- |
| Small | 3/3 / 3/3 | README-only changes; no explicit Skill invocation or adaptive workflow read in toolkit events. |
| Medium | 3/3 / 3/3 | Only validator and packaging-test files changed; no explicit Skill invocation or adaptive workflow read in toolkit events. One toolkit session had a permission denial. |
| Large | 0/3 / 0/3 | All three toolkit agents edited before stating the complete requested readiness gate. Two baseline agents stated all gate items before editing; the third stated them but stopped without editing after a denial, so pre-edit gate compliance for that arm is not applicable. |

Five Large candidates (two baseline and three toolkit) changed `validate.py`'s
unknown-argument behavior and failed the independent compatibility check. The
remaining baseline agent stopped without implementation after a denied command;
its independent evaluator failed because JSON mode was absent. All six Large
agents encountered at least one denial. Independent packaging and generated
file checks returned zero in every arm, but do not establish that the agent ran
the requested checks or that the Large task was completed.

No explicit `Skill` invocation or `adaptive.md` read appeared in any toolkit
event stream. Discovery alone does not demonstrate routing, and the absence of
an observed read does not prove what the model inferred from other context.
The Small median time was 4.950 s baseline and 3.535 s toolkit; median measured
tokens, including input, output, cache creation, and cache reads, were 33,631
and 24,825 respectively. Three pairs, prior exposure to these prompts, changed
toolkit content, and permission denials limit interpretation. No causal claim
or broad effectiveness claim follows from these results.

**KB-207 remains open:** these trials provide negative evidence for the
requested routing and toolkit readiness behavior, not successful verification.
Investigate discovery and activation, revise the narrowest relevant guidance,
then use independently specified scenarios with matched permissions, an
implicit complexity classification, pre-edit event review, and the Small
overhead measurements to reassess. Preserve this record and previous pilot
results. The P0 release gate remains not met.
