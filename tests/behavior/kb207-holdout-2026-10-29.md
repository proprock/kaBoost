# KB-207 holdout scenario — 2026-10-29

A scenario not used while tuning routing: add an opt-in `--output-dir DIR` option to
`scripts/build.py` ([prompt and runner](run_routing_experiment.py), [independent evaluator](acceptance_output_dir.py)).
The prompt asks only to "preserve existing behavior" and to run focused checks. The contracts the evaluator
checks (positional `build(root, check)` and `expected_files` shapes used by `validate.py` and the packaging
tests, refusal of unknown files and symlinked output, default output and exit codes) are discoverable from
`build.py` itself, its caller `validate.py`, and the packaging tests. The evaluator passed a reference
solution (7/7), failed the unmodified source on the feature tests, and failed a solution that reordered
`build()` parameters on the API and default-behavior tests.

Twenty uninstrumented Claude Code 2.1.308 / `claude-sonnet-5-5` medium-effort sessions on the frozen pilot
commit `b1d3f01` ([per-session record](kb207-holdout-2026-10-29.csv)): ten **baseline** (no toolkit) and ten with
the adopted toolkit from [ADR 006](../../docs/decisions/006-planning-entry-point.md); order shuffled with a fixed
seed, four workers, USD 0.40 cap, total USD 1.86. The authenticated profile was reused; permissions match
[the routing experiment](kb207-routing-experiment-2026-10-29.md). Raw events are not durable.

| Measure (10 sessions each) | Baseline | Toolkit |
| --- | --- | --- |
| Independent acceptance passed | 10 | 10 |
| Existing packaging tests pass in the final checkout | 10 | 10 |
| Planning skill invoked | 0 | 10 |

| Mean cost / mean wall time | USD 0.074 / 24.8 s | USD 0.112 / 34.0 s |

Observations:
- **Ceiling, not discrimination.** Both arms passed every independent check, so this scenario does not show
  an outcome benefit and cannot support one. The earlier Large scenario had the opposite problem (0 passes in
  every arm). A scenario where baseline passes about half the time is still needed.
- **Process differed clearly.** The toolkit arm invoked the planning skill in every session and ran the
  packaging tests itself in every session, against one in ten for baseline. Whether that matters for outcomes is
  not shown here: baseline reached the same correct result without running them.
- **Contract discovery was partial.** Half of the toolkit sessions looked at a dependent file before editing, against
  one in ten for baseline (the check is a text match on `validate.py` / `tests/packaging` in tool inputs and is crude).
- **The written gate is still not observed.** No session in either arm emitted criteria, non-goals and an
  alternative as visible text before editing, even after invoking the skill.
- **Overhead.** The toolkit arm cost 51% more and took 37% longer on this feature-sized task. The Small-task
  overhead gate is measured separately and was unchanged in the routing experiment; this task is not Small.

Limits: one scenario, one model and effort, ten sessions per arm, a ceiling on the outcome measure, text-match
metrics, a reused profile, and permission denials in about one session per arm. KB-207 remains open.
